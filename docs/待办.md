## 目标平台验收与故障演练

先确认隔离环境、允许的操作范围、数据库、Worker 和 Human 身份，以及可用通知渠道。密钥通过受控配置注入，不粘贴到本文件。固定实际源码 SHA、镜像 digest、Worker 包 hash、部署配置和测试时间。

平台基础验收包括：容器启动与健康/鉴权反例；PostgreSQL 状态一致性、RLS/权限和两个扫描器并发恢复；五角色任务消费、心跳、输出重放、同范围备用接管；真实人工审批和通知投递。外部 POS/维修尚使用替身时明确标记，不能归入真实接口通过。

| 故障 | 要取得的结果和证据 |
|---|---|
| Worker 断联/空心跳，主控卡住/重启 | 硬截止、有界恢复、主控监督和无重复委派 |
| 多扫描器竞争/重启 | 同一前序唯一有效后继，成功阶段不重做 |
| 旧 Worker 迟到提交 | 失效租约拒绝写业务或 checkpoint |
| 工单响应丢失、回执未知 | 原幂等身份和回执核对；未知转人工，不重复建单 |
| 审批/维修等待、拒绝、逾期 | 释放执行资源、原对象唤醒、超时升级，不把 timeout 当批准 |
| 备用/数据库不可用 | 有界等待或升级，外部监测暴露故障、限制危险写 |
| 应急保护与正常流程汇合 | 仅预授权场景开启；遏制不重复，审批及独立核验仍有效 |
| 越权与通知旧代次 | 跨租户/门店、旧通知领取者/代次被拒，回执脱敏 |

记录真实 Project/Room/Task/incident 的委派、Skill name/version/digest、工具请求与身份、租约/检查点/回执和独立核验。使用以下命令校验真实导出，之后仍须人工核对原始日志与录像：

~~~bash
uv run dianxun agentteams-verify <真实证据文件> --output <校验报告>
~~~

校验器通过不代表证据来源真实，禁止复制 fixture 充当平台导出。每项失败修复后重跑受影响故障；外部记录统一关联 T03。
