# 店巡 Agent 技术说明

复核日期：2026-09-13。本文合并原验证、一致性、MCP 可靠性、Skill、身份、协同与模拟数据说明。参数和契约以[事实源](../config/project-facts.json)、[Policy](../config/policies/coldchain-demo.v1.json)、代码和版本化 Schema 为准。

## 2026-09-15 二轮反馈对应实现

- 检测、风险建议和独立设备核验共享时间归一、去重与证据时效门禁。单样本、长缺测、未来/过期数据不能支持放行；人工测温绑定事件、商品批次、设备、仪器校准与商品测点。
- 整批 transferred/disposed 不再仅凭状态通过终态判定：必须有独立 Human/ScenarioEngine 记录的当前动作回执、数量和接收/销毁信息。缺证仍保持限制；真实数据来源、人员身份和物理真伪另验。
- ScenarioEngine 将每个事件和去重标记放入同一事务；PostgreSQL 使用事件 advisory lock，避免失败留下部分状态或并发重复执行。reset 仍只允许隔离的合成运行。
- PostgreSQL P0001 区分月首日错误、维护窗口拒绝和其他策略拒绝；应用回滚，返回 sqlstate 与 retryable=false，不返回数据库原始诊断。条件集成测试新增实际 guard 与 pgvector 路径，尚无实例实跑结果。
- scripts/capture_replay.py 在全新本地运行后封存 DB、逐条 Trace/审计和版本；scripts/replay.py 校验后只读回放，不重新执行。真实 AT/PG 导出接线、托管恢复、cron/归档与业务价值仍待外部验收。

字段与操作见[服务端交接](operations/finals-server-handoff.md)，状态只在[统一待办](待办.md)维护。本轮无数据库列迁移；缺少新凭证的旧记录需补证再验，不自动补齐或解除限制。

后续实现已补：runtime_ingest_scenario 将摘要匹配且已应用的场景事件原子接入运行协议；runtime_link_platform 按 Worker/assignment/版本关联平台消息和服务器输出摘要，真实性仍待原始导出核验。/operations 使用租户/门店范围内的只读数据库快照展示事件档案。capture_runtime.py 对已有 SQLite/PG 运行库封存，PG 逻辑视图与 pg_dump 共享导出快照；replay.py 支持版本 2 离线查看，恢复后另库逐表对账。Trace 为独立采集边界，PG/AT实机验收继续保留待办。

## 架构与身份

IncidentService 是业务状态唯一入口。LocalDemoAdapter 使用确定性 ScenarioEngine 驱动有状态外部替身；AgentTeams Worker 通过 /runtime 连接同一业务核心。本地 Demo/M4 不调用大模型，目标部署的模型声明不能当作实际模型调用证据。

| 身份 | 职责 | 权限边界 |
|---|---|---|
| Framework Manager | 接收外部任务、选择 Team、汇总 | 框架实体，不计入五个业务 Agent，不直接执行领域动作 |
| Orchestrator | 开事件、委派、协调阶段与受控 reopen | 不冒充其他 Worker，不批准处置或自报业务成功 |
| Sentry | 检测、数据质量与遏制请求 | 只读；停售交给 Executor |
| Diagnoser | 批次暴露建议、根因假设与证据缺口 | 只读；建议不直接改变库存 |
| Executor | 停售、申请审批、工单与获批处置 | 不能自批、自验、自行关闭事件 |
| Auditor | 独立重查、release guard、最终核验与复盘 | 不直接执行受控库存写，不用 Executor 的一句完成代替事实 |
| Human | 独立审批、人工证据；另可配置运维身份 | 不属于五个 Agent；运维 Token 不注入模型，也不能领取 Worker 任务 |
| ScenarioEngine | 固定场景中的合成审批与设备变化 | 仅为本地测试替身，不是真实员工或平台身份 |

/mcp 的共享 MCP_TOKEN 只读；业务写需要 MCP_ACTOR_TOKENS_JSON 的可信 Actor 映射。/runtime 使用独立 DIANXUN_RUNTIME_TOKENS_JSON，将每个 Token 绑定到 actor、worker_id、tenant_id、store_id；不接受请求体自报角色或共享 Token。部署与调用顺序见[运行手册](operations/runtime-recovery.md)和[AgentTeams](../agentteams/README.md)。

## 业务流程与成功条件

| 领域阶段 | runtime 协调步骤 | 结果 |
|---|---|---|
| DETECT_CONTAIN | DETECT / Sentry → CONTAIN / Executor | 发现并先遏制受影响商品 |
| DIAGNOSE_DECIDE | DIAGNOSE_DECIDE / Diagnoser | 关联根因和逐批次风险建议 |
| EXECUTE | EXECUTE / Executor | 按策略审批、维修及处置 |
| VERIFY | VERIFY / Auditor → RELEASE / Executor → FINAL_VERIFY / Auditor | 独立核验、必要的受控解禁、解禁后重查 |
| LEARN | LEARN / Auditor | 再次核验后由服务调用 IncidentService 关闭，生成复盘 |

无需解禁时 RELEASE 为检查后的空操作。Context completed、成功 checkpoint、工单 done、设备温度恢复都不能单独证明 Incident CLOSED 或商品可售。

查询 partial 不能写成功 checkpoint。HTTP runtime 只有取得完整且失败的独立核验、正确角色及版本，才允许 runtime_reopen；其新一轮从 CONTAIN 开始。LocalDemoAdapter 的场景 F 则回到 EXECUTE/BLOCKED，不能混用两种回开语义。已关闭事故需要新建事件。

| Skill | 当前版本 | Owner | 用途与边界 |
|---|---|---|---|

| [review-report](../skills/review-report) | 1.1.0 | Auditor | 复盘及待审核知识候选 |

九个目标 Skill 中另外三个为 cross-store-benchmark（P1）、restock-order-gen（P2）、price-tag-check（P2），其范围见[Skill 索引](../skills/README.md)及 planned 目录；不能算进六个 P0 Worker 契约。

每个 P0 目录保存用途、输入、输出、调用、失败、安全、复用、协同和版本约束，以及 Schema、正反例。[运行时装饰器](../src/dianxun/skills/contracts.py)在实际函数返回时校验 output。结构合法不等于输入真实或业务建议正确。

[Registry](../skills/registry.json)记录 name/version/digest；Trace 保存 release identity、channel 和 registry_version。stable/canary 使用确定性摘要分桶，retired 禁止新路由，旧 Trace 不伪造版本。Worker ZIP 从[包源目录](../packages/dianxun-worker)生成，不手工改 ZIP；固定下载引用见[AgentTeams 配置](../agentteams/README.md)。

## MCP 工具与错误语义

/mcp 默认精确公开 12 个 P0 工具，完整参数以[服务端工具 Schema](../src/dianxun/mcp/server.py)和[实现](../src/dianxun/mcp/p0.py)为准。/runtime 另有独立工具目录，不计入 P0 的 12 个。

| 查询 | 主要事实 |
|---|---|
| query_device_context | 温度、质量、健康、门、电源和维护上下文 |
| query_inventory_batches | 批次、存储策略、处置及安全状态 |
| query_sales_holds | 当前停售和解除状态 |
| query_workorder | 工单、维修状态与回执 |
| query_approval | 审批状态、决定人、动作与原因 |

| 动作 | 允许主体 | 前置条件 |
|---|---|---|
| apply_sales_hold | Executor | Policy 允许的先行遏制 |
| release_sales_hold | Executor | 有效审批及新鲜的 Auditor release_guard |
| apply_batch_disposition | Executor | quarantined 为预授权；transferred/released/disposed 需对应审批 |
| create_workorder | Executor | 比赛策略中预算大于 2000 元需批准 |
| create_approval | Executor | 仅创建 pending，不能视为批准 |
| decide_approval | Human；测试中为 ScenarioEngine | 独立决定，不能由 Agent 自批 |
| record_manual_evidence | Human；测试中为 ScenarioEngine | 记录证据引用和摘要，不把敏感原件写入 Trace |

三个 P1 知识工具 search_knowledge、create_knowledge_candidate、review_knowledge_candidate 默认关闭，需 DIANXUN_ENABLE_P1_TOOLS=1。候选先审核、脱敏再发布；检索只返回通过门禁的发布条目。知识检索不等于自动改变业务策略；当前默认 Hash Embedding 不代表已部署生产检索服务。

当前 ToolEnvelope 的字段为 ok、data、error、request_id、source、source_ts、partial、audit_ref，见[Schema](../schemas/mcp-envelope.v1.schema.json)；没有另一套 status/evidence/meta 顶层字段。HTTP 200 只表示传输完成，必须核对 ok、partial 和 error。INVALID_ARGUMENT、FORBIDDEN 不盲目重试；APPROVAL_REQUIRED 进入原审批等待；APPROVAL_INVALID 重查；INVALID_STATE 重读状态。审批 timeout 与人工 rejected 分开，都不能当批准。

## 事务、版本与恢复

| 层 | 实现 | 限制 |
|---|---|---|
| SQLiteStateStore | BEGIN IMMEDIATE、10 秒 busy_timeout、唯一约束 | 业务库不强制 WAL；同一文件写事务串行化 |
| 独立 ContextBus | WAL、tenant/task、TTL、expected_version、lease/checkpoint | 独立协调演练，不自动导入业务 runtime |
| RuntimeContextBus | 业务库 runtime_contexts；与领域动作共用事务 | Context 版本不能替代 Incident 的业务判断 |
| Incident 聚合 | case_json.version CAS、核验记录原子提交 | 旧快照被拒；不覆盖较新事实 |
| 恢复容量决策 | SQLite 写事务或 PostgreSQL 事务 advisory lock | 按同门店 scope 竞争；目标 PostgreSQL 仍需实例测试 |

嵌套事务使用 SAVEPOINT；内部错误即使转换成工具结果，也回滚本次业务、审计和幂等记录，外层失败回滚全部变更。同一 idempotency_key 必须对应同一请求指纹，换 key 也不能绕过 action 唯一性制造第二次副作用。

/runtime 已实现后台巡查、空心跳约束、有效进展、硬截止、阶段总预算、有限重试、健康备用、容量、等待唤醒、未知回执与 Human 升级。正常调度不能绕过业务前置条件；受控应急停售默认关闭。参数、通知 Outbox、运维与兼容回滚统一见[运行与恢复](operations/runtime-recovery.md)。

当前业务适配器为同步数据库工具，副作用与回执同事务落库。未来接入真实 POS/维修网络写入时，必须采用短事务记录意图、事务外稳定幂等调用、短事务对账；本地回滚或关闭 socket 不能撤销已发生的外部操作，不承诺 exactly-once。

## HTTP 与观测

BoundedHTTPServer 默认 127.0.0.1:8080、最多 32 连接、10 秒绝对截止和 1 MiB body。满载返回 503，超限返回 413；重复 Content-Length、Transfer-Encoding 和非法长度被拒绝，不能用滴入请求持续刷新截止。

/live 为进程存活；/ready 和 /health 为数据库、初始化、Skill 与配置 runtime 后的扫描器就绪。/metrics 为固定低基数工具与恢复指标，默认无鉴权，应限制监控访问。没有生产 p99/SLA、通用 CircuitBreaker、gRPC 或 requests/tenacity 客户端的完成声明。指标口径与 PromQL 见[运行手册](operations/runtime-recovery.md)。
