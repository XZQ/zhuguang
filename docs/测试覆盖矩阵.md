## 2. 12 个 P0 MCP 工具的证据边界

### 2.1 Registry 与 Schema

`test_registry_is_exactly_the_twelve_p0_functions` 固定 5 个查询和 7 个动作的精确 registry：

| 类型 | 工具 |
|---|---|
| 查询 | `query_device_context`、`query_inventory_batches`、`query_sales_holds`、`query_workorder`、`query_approval` |
| 动作 | `apply_sales_hold`、`release_sales_hold`、`apply_batch_disposition`、`create_workorder`、`create_approval`、`decide_approval`、`record_manual_evidence` |

HTTP/runtime schema 测试还验证缺失参数、非对象参数、请求体上限和鉴权边界。这里的
“12/12”表示每个工具都在 registry/契约或场景调用路径中有映射，不表示每个工具都有一个
独立同名测试方法，更不表示 100% 行或分支覆盖。

## 3. 六个 P0 Skill 输出契约

`test_all_p0_skill_packages_have_valid_contracts_and_examples` 会校验六个 Skill 的 input/output
Schema 与成功/失败样例。运行时代码还通过 `src/dianxun/skills/contracts.py` 装饰六个主线
入口，并在函数返回时校验 output Schema：

- `detect_coldchain_event`
- `coldchain_risk_assess`
- `diagnose_coldchain_hypotheses`
- `dispatch_stateful_workorder`
- `outcome_verify`
- `review_incident`

测试会删除一个必填输出字段并确认运行时校验明确拒绝，以防静态样例通过但实际返回结构漂移。

`tests/test_skill_registry.py` 另行校验 6 个 stable release 与 manifest/内容 digest 一致、
SemVer 兼容分类、SHA-256 确定性 canary 分桶、retired 禁止新路由，以及旧 Trace DB 迁移后
真实 Skill Span 含 `skill_name/version/digest/channel/registry_version`。AgentTeams 动态证据测试
还会拒绝调用 Trace 中版本或 digest 与 Worker provenance 不一致的证据包。

## 5. 分层替身策略

| 层级 | 当前做法 | 证据含义 |
|---|---|---|
| SQLite | 每个核心测试使用隔离的临时真实数据库 | 验证真实 SQL、事务、约束和序列化行为 |
| Policy | 加载真实版本化策略文件 | 验证 actor、action、risk、approval 规则 |
| 业务时间 | 虚拟时钟 | 可重复地推进审批超时和 Evidence 时间戳 |
| 外部系统 | 有状态本地 Adapter/ScenarioEngine | 验证确定性输入、输出和状态变化；不证明真实门店接入 |
| HTTP | 本地标准库 HTTP server | 验证协议、body/auth/tool allowlist 边界 |
| PolarDB | 条件集成测试 | 只有提供外部实例时才形成运行证据 |
