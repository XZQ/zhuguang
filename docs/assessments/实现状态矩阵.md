## 状态定义

| 状态 | 使用条件 |
|---|---|
| 已实现 | 代码/材料存在，相关自动化验证通过，并有对应真实调用或可视检查 |
| 模拟实现 | 通过有状态 Mock 产生真实输入、输出和状态变化，且边界明确 |
| 规划 | 只有设计、接口或生产替换方向 |
| 外部待验证 | 仓库产物已准备，但必须在 AgentTeams、Kubernetes 或企业目标环境运行后确认 |

## 冻结事实

- 拓扑：1 个 Framework Manager + 5 个业务 Agent。
- 流程：5 个业务阶段；赛事 8 项要求作为横向证据检查。
- Skill：9 个目标 Skill，其中 P0 6、P1 1、P2 2。
- MCP：12 个 P0 函数，其中查询 5、动作 7。
- 主场景：冷柜失温；补充场景：缺货、价签。
- AgentTeams：`v1.2.3`，commit `223ddc2b8073e4c8b93bcbb15e1d717f196c04d9`，CRD `agentteams.io/v1beta1`。
- 模型：目标 Manager/Worker 声明 `qwenpaw + qwen3.5-plus`；本地 Demo/M4 不调用 LLM；凭证运行时注入，费用依提供商，替换模型需回归。
- 官方用云 Skill：当前 P0 全部为自定义可复用 Skill；官网/手册 FAQ 措辞冲突待组委会确认。
- MCP 身份：本地 Adapter 支持共享 Bearer 或 Token → Actor 映射；当前静态 AgentTeams Deployment 未绑定动态 Worker `gatewayKey`，状态为外部待验证。
- Worker ZIP SHA-256：`0a905c2b33dc28fb0b2427349fa2ed59af35c1c85afee9b1e54a7f1f7c832fea`。
- 冷链策略：`coldchain-demo:1.0.0`，仅用于比赛合成场景。
- 业务状态唯一入口：`IncidentService`。

## 当前限制与风险

1. AgentTeams `state: Running` 是 YAML 期望状态，不是实际集群证据。
2. ScenarioEngine 模拟 Human 审批和人工证据，只证明状态语义。
3. 六场景全部为合成数据，100% 指标不能外推为生产准确率。
4. 冷链阈值没有商品标签、HACCP 和所在地法规背书，不能用于真实放行。
5. RAG、自动回滚、Nacos、Higress、RocketMQ、PolarDB、LoongSuite 仍是规划/替换方向。
6. 缺货和价签入口通过回归，但仍使用改造前业务核心，只作为补充展示。
7. 最终视频若要展示 AgentTeams，必须在外部环境真实录制，不能用本地输出或静态截图冒充。
8. 当前没有真实模型调用账单；6/6、42 项测试和 M4 指标不能作为 `qwen3.5-plus` 效果或成本证明。
9. 本地业务角色门禁不等于部署身份鉴权；当前静态 ClusterIP 直连未证明动态 Worker Bearer 已映射为正确 Actor。

## 更新规则

- 数字、能力、版本变化时先更新 `config/project-facts.json`，再同步 README、01～08、状态矩阵、AgentTeams README 和演示稿。
- 每次评测以 `uv run dianxun evaluate` 重建 evidence，不手工改结果。
- 只有取得真实平台动态证据后，才能修改 M3 和最终视频状态。
- 每个里程碑提交后必须 push，并核对本地/远端 SHA 与分歧 `0 0`。
