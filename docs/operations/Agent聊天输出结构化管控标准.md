# 店巡 Multi-Agent 聊天输出结构化管控标准 (v2.0)

> **生效范围**：逐光团队「店巡」系统所有 Agent（Orchestrator、Sentry、Diagnoser、Executor、Auditor、Manager）在 Matrix 团队群及所有协作频道中的消息输出。  
> **制定目的**：彻底消除原始 JSON 堆砌、纯英文报错、机器碎屑与晦涩日志，实现“人类一眼看懂业务进度，系统完备保留审计线索”。

---

## 1. 核心铁律（Three Golden Rules）

1. **业务大白话优先（Business-First）**：
   - 严禁任何 Agent 在群内直接倾倒未排版的原始 JSON 字符串、Python 堆栈或调试日志。
   - 消息第一句话必须是清晰的人类自然语言，说明发生了什么、严重程度及业务影响。
2. **严禁英文碎屑与复读（Zero English Artifacts）**：
   - 全链路强制规范中文输出，严禁输出 `"The orchestrator is asking me to..."` 或 `"standing by..."` 这类模型自言自语。
3. **技术元数据下沉折叠（Metadata Footing）**：
   - 机器调度与审计所需的元数据（如 `incident_id`、`trace_id`、`lease_expires_at` 等）统一收敛至卡片底部紧凑单行代码块中，满足机器解析同时不打扰人类视线。

---

## 2. 通用四段式看板卡片结构 (Unified 4-Section Card)

所有 Agent 向团队群发送汇报或交接消息时，**必须严格遵循以下四段式排版**：

```markdown
【[状态图标] 角色标识 · 当前阶段动作】
🎯 核心摘要：一句话大白话业务结论（清晰说明发生了什么、结果如何）
--------------------------------------------------
📊 现场指标与证据：
• 涉及对象：[门店名称 / 区域 / 设备编号 / 关联商品批次]
• 关键读数：[当前值 vs 阈值，如：实测 8.2℃ (安全上限 ≤ 4.0℃)]
• 处置动作：[已完成动作 / 处置方案]
--------------------------------------------------
🚦 下步流转与指令：
• 下一责任人：[@Orchestrator 编排调度 / @Executor 下发执行 / ...]
• 人工介入指示：[✅ 自动流转无需介入 | ⚠️ 需 @admin 人类审批确认]
`[审计追踪] incident_id: <ID> | checkpoint: <REF> | trace: <ID>`
```

## 3. 五大角色标准输出模板与示范

### 3.1 Sentry（巡检预警员）
* **定位**：发现异常、界定影响、拉响警报。
* **标准示范**：
```markdown
【🚨 Sentry 巡检员 · 发现冷链超温异常 (DETECT)】
🎯 核心摘要：检测到 A02 门店 3 号冷柜持续超温，已触发冷链食品安全黄色预警！
--------------------------------------------------
📊 现场指标与证据：
• 异常对象：A02 门店 3 号鲜奶立式冷柜 (DEV-COLD-03)
• 关键读数：当前温度 8.2℃（安全标准 ≤ 4.0℃，超标持续 35 分钟）
• 影响批次：在柜鲜奶制品 42 盒，货值约 680 元
• 紧急动作：已自动在 POS 系统对受影响批次打上「暂停销售」预锁
--------------------------------------------------
🚦 下步流转与指令：
• 下一责任人：@Orchestrator 请推进遏制与根因排查
• 人工介入指示：✅ 当前处于自动安全锁定阶段，无需人工干预
`[审计追踪] incident_id: INC-COLD-A02-0918 | trace: tr-sentry-8821a`
```

---

### 3.2 Diagnoser（诊断分析员）
* **定位**：多维排查、排除误报、锁定根因。
* **标准示范**：
```markdown
【🔍 Diagnoser 诊断员 · 根因分析完成 (DIAGNOSE)】
🎯 核心摘要：完成设备传感器与历史工单排查，定位故障根因为「冷凝风扇电机轴承卡阻」。
--------------------------------------------------
📊 诊断矩阵与依据：
• Top-1 根因：冷凝风扇转速仅 320 RPM（额定 1200 RPM，置信度 92%）
• 排除项说明：压缩机供电正常（220V）、制冷剂压力正常（0.45 MPa，排除泄漏）
• 关联知识：命中《冷链散热电机常见高频故障库》(KB-REF-4421)
• 处置建议：推荐下发电机强制高频脉冲重启脚本
--------------------------------------------------
🚦 下步流转与指令：
• 下一责任人：@Orchestrator 决策并生成执行计划
• 人工介入指示：✅ 方案已就绪，等待下发
`[审计追踪] incident_id: INC-COLD-A02-0918 | confidence: 0.92 | trace: tr-diag-9912c`
```

### 3.3 Executor（动作执行员）
* **定位**：受控写、隔离危险、触发审批。
* **标准示范**：
```markdown
【⚡️ Executor 执行员 · 动作就绪 / 等待人类授权 (EXECUTE)】
🎯 核心摘要：物理隔离动作已完成；冷柜电机重启属于 L2 级工控写操作，等待人类审批！
--------------------------------------------------
📊 动作状态与清单：
• 已执行动作：✅ 鲜奶商品条码停售封存生效 (LOCK-SKU-8821)
• 待执行动作：⏸️ 远程下发冷凝电机强制高频重启指令 (ACTION-RESTART-0918)
• 安全级别：L2 级受控操作（生产工控安全公理红线）
--------------------------------------------------
🚦 下步流转与指令：
• 人工介入指示：⚠️ 请人类管理员 @admin 审核并在群内回复「批准」或点击审批卡片
• 保护机制：若 15 分钟内未获批，系统将维持物理停售并降级派发线下驻店师傅工单
`[审计追踪] incident_id: INC-COLD-A02-0918 | action_id: ACT-4410 | trace: tr-exec-0102b`
```

### 3.4 Auditor（独立审计员）
* **定位**：反自验（Anti-Self）、双重验证、固化证据。
* **标准示范**：
```markdown
【🛡️ Auditor 审计员 · 独立双重闭环核验通过 (VERIFY)】
🎯 核心摘要：设备恢复达标与商品安全封存已完成独立反自验复核，确认符合安全关单标准！
--------------------------------------------------
📊 独立核验证据：
• 设备恢复核验：冷柜温度已回落至 3.4℃（达标），风机转速 1180 RPM（达标）
• 商品安全核验：受影响 42 盒鲜奶已全量转移至报损冷库，柜台售出数为 0（未流入市场）
• 证据防篡改包：已生成不可逆证据哈希 `sha256:7f83b1657ff1...`
--------------------------------------------------
🚦 下步流转与指令：
• 下一责任人：@Orchestrator 满足双重安全关闭条件，建议予以结案归档
• 人工介入指示：✅ 审计合规，闭环通过
`[审计追踪] incident_id: INC-COLD-A02-0918 | evidence_ref: EVI-PKG-20260918 | verify: PASS`
```

## 4. 落地与执行保障

1. **Prompt 级强约束**：在所有 Worker 的 `SOUL.md` 与 `AGENTS.md` 中置顶本规范，强制要求格式化输出；
2. **拦截与纠偏机制**：Orchestrator 接收到非标准格式的 Worker 回执时，要求其重新按卡片格式格式化后入库；
3. **人类监督者友好**：人类管理员 `@admin` 在 Element 群内无需费力阅读技术字段，通过四段式卡片 3 秒内即可完成情况获知与审批决断。
