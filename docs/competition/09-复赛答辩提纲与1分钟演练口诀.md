## 一、3 分钟项目与架构陈述（口诀台词）

- **00:00 - 00:40 痛点命题（40秒）**：
  “各位评委老师下午好！我是逐光队，今天汇报的作品是面向连锁便利店的异常安全闭环基础设施——店巡 Agent。
  在便利店冷链运维中，冷柜失温是典型痛点。但现有方案往往止步于‘发告警’或‘派维修工单’，忽视了两个核心痛点：
  第一，设备恢复不等于商品安全——即使冷柜修好降温了，超温暴露超标的鲜奶依然已经变质；
  第二，工单完成不等于事件关闭——执行维修的人绝不能自己验收自己。
  因此，店巡 Agent 解决的不是单纯告警，而是让异常从发现、停售遏制、根因诊断、受控处置，真正走到独立稽核与安全闭环。”

- **00:40 - 01:40 多 Agent 协同与职责分离（60秒 · 核心得分点）**：
  “在架构设计上，我们基于 AgentTeams v1.2.3 构建了 1 个 Manager + 5 个业务 Worker 的网状拓扑，坚持严格的职责分离：
  1. Orchestrator（总控编排）：全局目标拆解与阶段推进，只调度协调，没有任何领域写权限；
  2. Sentry（巡检守卫）：L0 只读权限，时序数据质量检验并发现失温，第一时间发出紧急遏制请求；
  3. Diagnoser（根因诊断）：L0 只读权限，综合门磁与除霜特征排查压缩机故障，同时计算每批次商品的超温暴露时长；
  4. Executor（受控执行）：L1/L2 受控写权限，下发 POS 停售锁、发起工单。所有操作受 Policy 拦截，高风险操作强制触发人工审批（HITL），且所有写操作严格幂等；
  5. Auditor（独立稽核 · 核心红线守门员）：执行者不能自证成功！Auditor 独立调用接口重新重查设备与商品双重事实，只要商品仍不安全，坚决阻断关闭或回开（Reopen）！”

- **01:40 - 02:30 技术基座与工程落地（50秒）**：
  “在底层 Infra 与可验证工程上，我们拒绝概念 PPT：
  1. 真实部署基座：部署于广州 Linux 生产服务器上的 AgentTeams 控制面与 5 个 Worker 容器，接入阿里云百炼平台 qwen3.8-max；
  2. Skill 九要素契约：规范治理 6 个核心 P0 Skill（输入输出 Schema、调用前置条件、依赖工具与安全边界）；
  3. 状态双底座：支持本地零依赖评测的 SQLite 底座，以及托管环境的 PolarDB PostgreSQL（audit_log 剥夺 UPDATE/DELETE，实现只增不可篡改审计）；
  4. 确定性回归验证：覆盖 6 大全场景，沉淀了 45 份关键 Evidence 证据链和 26 条阶段 Trace，错误放行率与违规关闭率全部为 0。”

- **02:30 - 03:00 切入 Demo（30秒）**：

## 三、评委高频攻防问题速查

1. **为什么用 5 个 Agent 而非 1 个 Agent + Prompt？**
   - 运动员不能兼任裁判员；单 Agent 无法做接口级权限硬隔离（L0 只读 vs L1/L2 受控写）；必须引入独立的 Auditor 查证客观事实。
2. **在 AgentTeams 上做了哪些 Infra 创新？**
   - 有状态业务中枢（IncidentService 支持掉线恢复）；Token → Actor 强鉴权网关；统一 Evidence 哈希与 Trace 存证。
3. **如何防止大模型乱决策？**
   - Policy 门禁（敏感操作挂起触发 HITL 人工审批）；全量写操作强制附带幂等键；数据库底层剥夺 UPDATE/DELETE 保证审计不可篡改。
