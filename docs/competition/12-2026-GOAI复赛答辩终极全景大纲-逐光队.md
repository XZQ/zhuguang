## 第一章：立项背景与物理真实痛点（传统监控三大致命盲区）

连锁便利店（如 7-Eleven、美宜佳）和生鲜门店的利润极薄，高度依赖物理冷链设备（冷藏立风柜、冷冻岛柜、鲜食保温柜）。但在真实运维中，现有监控软件存在三大致命断层：

### 1. “告警风暴与形式主义”断层（反面教材：智感温盾）
- 传统物联网只做简单的单点硬阈值报警（超 8°C 就报警）。全网成百上千台设备每天产生几百甚至上千条告警（如现实系统中单日活跃告警达 608 条），店员和运维严重疲劳麻木；
- 系统给出的唯一处置手段竟然只有一个敷衍的**【标记已解决】**按钮！点一下按钮，告警红灯变绿了，但冷柜依然失温，陷入**“告警已读，事故未消”**的假闭环。

### 2. “设备恢复 ≠ 商品安全”断层（行业最大安全盲区）
- 冷柜跳闸 2 小时后重新来电或维修换件，温度降回了 4°C，传统系统显示设备正常。
- **但柜内的巴氏鲜牛奶在室温超标暴露超过 30 分钟早已不可逆变质！** 店员误以为“设备绿了商品就安全”，导致变质牛奶流向收银台，引发恶劣食品安全中毒投诉与巨额处罚。

### 3. “执行与验收一体”的自验漏洞
- 报修、维修、验收由同一个人或同一家外包商完成，缺乏独立监督制衡，**“执行者自己宣布自己修好了”**就能结案，缺乏第三方查证客观事实的机制。

## 第四章：端到端技术方案：五层解耦架构全景

店巡 Agent 严格采用分层解耦的工程架构：

1. **L1 感知接入层（IoT Fleet Telemetry）**：
   - 接收 512 台设备的时序遥测（温度、湿度、门磁、电流），集成 **Westgard 质控法则（±3SD 阈值线）** 消除假报警；
2. **L2 核心业务中枢层（IncidentService）**：
   - **唯一业务事实入口**：维护确定性的五阶段状态机（`DETECTED ➔ CONTAINED ➔ DIAGNOSED ➔ DISPATCHED ➔ VERIFIED ➔ CLOSED`）；
   - **双底座存储机制**：本地 SQLite 零依赖评测引擎 + 生产级 PolarDB PostgreSQL；
   - **审计硬约束**：底层彻底剥夺 `audit_log` 的 UPDATE 和 DELETE 权限，只允许 INSERT，实现只增防篡改审计；
3. **L3 协同智能体基座层（AgentTeams v1.2.3）**：
   - 部署在广州 Linux 服务器上的生产容器集群，基于 Matrix 协议通信，驱动 1 Manager + 5 Workers，接入阿里百炼 `qwen3.8-max`；
4. **L4 业务工具生态层（12 个 P0 标准 MCP）**：
   - 设备时序遥测、商品批次查询、POS 停售控制锁、移动端审批单、服务商急修工单等 12 个微服务解耦封装；
5. **L5 安全防御治理层（Guard & Policy）**：
   - 角色鉴权网关（Role Token）、操作强幂等校验（`idempotency_key`）、店长移动端双签审批（HITL）。

### 各 Agent 权责清单与制衡设计
1. **Orchestrator（总控编排 · Leader）**：负责跨阶段协同与汇总，**无任何领域写权限**，避免总控大模型因幻觉乱改数据；
2. **Sentry（全网守卫 · L0 只读）**：以 30 秒周期扫描全网，Westgard 去噪与断流校验，锁定异常单柜发起 `request_containment`；
3. **Diagnoser（根因专家 · L0 只读）**：排查门磁与除霜特征，锁定压缩机故障（0.94置信度）；同时积分计算商品暴露时长（如 42min > 30m）；
4. **Executor（受控执行 · L1/L2 写）**：下发 POS 停售锁、派发急修工单，全量写操作强制附带幂等键；
5. **Auditor（独立稽核 · 核心红线守门员）**：**执行者不能自证成功！** 必须开辟干净独立上下文，重查两套客观事实，变质品坚决阻断放行或回开事件；
6. **Policy/Guard（安全门禁）**：大额维修或商品报损强制挂起，推送店长手机端完成人工审批（HITL）。

## 第六章：五大硬核技术亮点与底层创新壁垒

### 亮点 1：物理世界“双重状态解耦模型”（业界首创）
显式解耦 **物理设备状态（Device State）** 与 **商品资产安全状态（Asset State）**。形成铁律：**设备恢复不等于商品安全，工单完成不等于事件关闭**。

### 亮点 2：反自验“独立稽核与阻断机制”（Anti-Self-Verification）
彻底终结传统单体大模型“自己干自己验收”的自圆其说漏洞。Auditor 拥有独立数据核验接口与**一票否决权（阻断放行与回开 Reopen）**。

### 亮点 3：引入临床级 Westgard 质控法则（时序智能去噪）
将高精密度实验室的 **Westgard 质控法则（±3SD 阈值线、系统漂移）** 引入零售时序，区分开门拿货的瞬时温度波动与压缩机故障持续失温，误报率下降 90% 以上。

### 亮点 4：Skill 九要素标准化契约治理
6 个核心 P0 Skill 严格按照**用途、输入输出 Schema、前置条件、工具依赖、失败重试、降级策略、安全边界与复用价值**九要素治理，与具体业务完全解耦。

### 亮点 5：金融级不可篡改审计流与全链路存证
数据库层收回 `audit_log` 的 UPDATE 和 DELETE 权限，全流程打上 **SHA-256 证据哈希包与 Matrix Trace ID**，全链路可穿透、可追责、无法篡改。

## 第十一章：【3 分钟评委问答】官方 4 大考核维度 8 大核心攻防题

### 维度 1：技术方案（AgentTeams 架构与底层机制）
- **Q1：为什么必须采用 AgentTeams 多 Agent 架构，而不是用一个超强的大模型配一长串 Prompt？**
  - **A**：“单个 Agent 在物理世界高风险操作中存在两大死穴：第一是**无法做接口级权限硬隔离**。在 AgentTeams 中，Sentry 只有 L0 只读权限，Executor 拥有受控写权限，Auditor 拥有独立稽核权限，从 Token 协议层杜绝越权；第二是**违反职责分离原则**。‘运动员不能兼任裁判员’，单 Agent 倾向于自证成功，必须由 Auditor 独立开辟干净上下文核验客观事实。”
- **Q2：你们在 AgentTeams 上做了哪些底层 Infra 创新？**
  - **A**：“三大核心 Infra 创新：第一是**有状态业务中枢（IncidentService）**，实现五阶段状态机与断点恢复；第二是**12 个标准 MCP 工具生态**，解耦跨网络服务；第三是**全链路 Evidence 哈希存证**，每次状态迁移均自动生成 SHA-256 哈希指纹与 Matrix Trace。”

### 维度 3：风险边界与安全机制（大模型防幻觉、HITL 审批、审计防篡改）
- **Q5：大模型经常出现‘幻觉’或‘失控调用’，你们如何确保不会乱派修、乱扣钱、乱停售？**
  - **A**：“四道纵深防御红线：第一，**Policy 门禁与 HITL 审批**：大额费用与商品报损强制挂起，店长手机端核准后才发放执行 Token；第二，**强幂等保证**：全量操作自带 `idempotency_key`，网络重试绝不二次扣费；第三，**Auditor 强制阻断**：设备修好不代表商品安全，超温变质强制阻断；第四，**只增防篡改审计**：数据库层收回 `audit_log` 的 UPDATE/DELETE 权限，只允许 INSERT。”

  - **A**：“我们在场景 D 中专门验证了超时降级：超过 15 分钟未审批，系统启动安全升级机制，自动通知大区品控经理，**同时维持 POS 停售锁不变**，绝不默认放行，始终以食品安全为最高优先级。”
