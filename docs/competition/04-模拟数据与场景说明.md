# 模拟数据与场景说明

## 1. 目的与边界

本项目用确定性合成数据验证冷柜事件状态语义、安全门禁和失败分支。数据只服务比赛 Demo，不代表真实门店分布、食品安全阈值、经营效果或生产准确率。

Seed、Scenario 和 ScenarioEngine 中的 Actor/审批人都是合成身份，只能验证角色规则与状态迁移；它们不是 AgentTeams Worker、真实员工或部署侧 Bearer 身份绑定证据。

代码入口为 [`../../scripts/generate_demo_data.py`](../../scripts/generate_demo_data.py)，不在文档目录保留可执行脚本副本。

## 2. 数据分层

| 路径 | 作用 | 是否版本化 |
|---|---|---:|
| `data/*.csv` | 缺货、价签等补充入口的静态样例 | 是 |
| `demo/state/seed.json` | 冷柜有状态世界的确定性初始快照 | 是 |
| `demo/state/scenarios/*.json` | A～F 场景、故障注入、ground truth 与预期终态 | 是 |
| `demo/state/runtime.db` | 本地 MCP/Demo 运行时 SQLite | 否，随时可重建 |
| `evidence/m4/*` | 六场景评测结果与报告 | 是，由评测命令重建 |

## 3. 生成与校验

所有命令从仓库根目录执行：

```powershell
# 生成默认 Seed
uv run python scripts/generate_demo_data.py

# 指定虚拟时钟和随机种子
uv run python scripts/generate_demo_data.py `
  --anchor-time 2026-08-28T09:00:00+08:00 `
  --seed 42

# 只校验仓库 Seed 是否可重复，不写文件
uv run python scripts/generate_demo_data.py --check

# 生成 Seed 后重置本地运行数据库
uv run python scripts/generate_demo_data.py --db demo/state/runtime.db
```

`--check` 会重新构造 Seed，并与 `demo/state/seed.json` 做 UTF-8 文本级比较；缺失或不一致时退出非零。

## 4. Scenario 约束

每个冷柜 Scenario 均需通过 `schemas/scenario.v1.schema.json`，并明确：

- `ground_truth` 与允许的候选假设；
- 禁止动作和必须动作；
- 预期 Incident/Work 终态；
- 必需 Evidence 与适用 Trace 阶段；
- 最大安全遏制时延；
- 可重复的故障注入及虚拟时间推进。

场景运行必须使用隔离的临时 SQLite/Trace 数据库。不得依赖上一次运行状态，也不得手工修改 `evidence/m4/results.json` 制造通过。

## 5. 验收命令

```powershell
uv run python scripts/generate_demo_data.py --check
uv run dianxun evaluate
uv run --group dev python -W error::ResourceWarning -m unittest discover -v
```
