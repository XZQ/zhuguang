01 · 第一性原理

3 PHYSICAL-DIGITAL AXIOMS
⏱️ 建议用时: 35 秒
🎯 核心抓手：剖析物理世界三大公理，揭示纯软件 Agent 在实体世界的崩溃 手势：伸出三根手指分别阐述

在实体连锁与工业场景中，现有的智能体系统往往面临一个共同缺陷：把纯软件的假设生搬硬套到物理世界。我们提炼出物理实体流程的三大不可逆公理：

第一，状态不对称——设备修好 ≠ 商品安全。
冷柜压缩机故障失温，师傅上门换好了零件，温度降回了 4°C，系统工单提示“已修复”。但物理世界有热力学惯性！在失温的数小时里，柜内的巴氏鲜奶可能早已微生物超标变质。

第二，执行不可逆——物理动作没有“代码假撤销”。
软件报错可以一键 git rollback，但物理世界的技工上门、零件更换、通断电、整批报损，都会产生真实责任与高昂成本。

第三，反自验闭环——执行者绝无权自证成功！
大模型执行者如果自己验收自己，必然陷入自证幻觉。执行者绝不能既当运动员又当裁判员！必须引入强物理隔离的外部 Auditor 重查客观物理真值。

针对上述挑战，我们构建了 VeriPatrol 三层解耦架构栈：

• 顶层：跨行业 Profile 插件。无论是零售冷链的 Arrhenius 动力学、医药温控的 GSP 规范，还是算力中心的结温功耗墙，均以 DSL 形式无侵入注入，通用核心代码 0% 业务硬编码；

• 中层：VeriPatrol 通用核心引擎。由确定性状态机 Orchestrator 驱动，包含质控哨兵 Sentry、因果大脑 Diagnoser、受控执行 Executor、带外预言机 Auditor，以及驱动模型进化的 AgentLoop；

• 底层：物理-数字交互总线。提供 500ms 数字拦截、Human-as-a-Tool 维修工单调度、外部客观物理传感器 Oracle，以及金融级只增审计流。

03 · 五 Agent 职责

5 KERNEL AGENTS
⏱️ 建议用时: 35 秒
🎯 核心抓手：点明 Executor 剥夺自验权、Auditor 手握一票否决权 对比：消融实验证明单体自验必漏检

在我们的系统里，5 个智能体各司其职，拥有不可僭越的职责边界：

• Orchestrator（调度引擎）：维护确定性状态机，拆解阶段，负责异步等待与超时升级，无任何领域写权限；
• Sentry（质控哨兵）：L0 只读监测，采用 Westgard ±3SD 走廊滤除瞬态毛刺与噪声；
• Diagnoser（推断大脑）：L0 只读建议，基于物理动力学模型做热应力定损，输出 Top-K 处方；
• Executor（执行机构）：拥有 L1 预授权数字熔断与 L2 物理调度权限，但被彻底剥夺了自验权；
• Auditor（独立预言机）：拥有一票否决权！独立重查外部传感器真值，只有设备与商品双重过关，才允许 Verified Close。

04 · 五阶段闭环

UNIVERSAL 5-STAGE PROTOCOL
⏱️ 建议用时: 35 秒
🎯 核心抓手：讲透 500ms 数字熔断到反自验独立重验的标准全生命周期 关键：设备与商品两条独立确认路径

任何一次现场异常，系统均会严格执行标准五阶段协议：

1. 数字熔断（Interlock）：Sentry 捕获持续偏离，500ms 内向 POS 和外卖中台下发数字熔断锁，切断对外销售，遏制风险外溢；
2. 动力学定损（Kinetics）：Diagnoser 结合牛顿冷却定律与 Arrhenius 积分，精确推算各批次食品的超温暴露应力；
3. 调度 Human Tool：将维修师傅抽象为异步工具，通过移动端 HITL 审批流派修，纳入 SLA 超时容灾；
4. 反自验独立重验（Oracle Verify）：Auditor 独立重查客观真值。设备恢复与商品安全走两条独立确认路径，双双通过才算成功；
5. 运行时演进（AgentLoop）：风险归零后闭环，全链路不可篡改 Trace 回流，驱动 Skill 与策略持续进化。

05 · 执行鲁棒性

6 FORMAL INVARIANTS
⏱️ 建议用时: 35 秒
🎯 核心抓手：剖析六大不变式，突出“保持遏制是正确安全结果” 核心场景：重点点名场景 E (红线)

我们通过形式化方法定义了六大执行不变式（A ~ F），覆盖所有边界分支：

• 场景 A：硬件修复且资产安全，双重验真成功放行；
• 场景 B/C：传感器抖动或开门气流扰动，自动识别去噪与自愈；
• 场景 D：人工审批超时，绝不擅自行动，自动升级区域负责人；
• 核心红线场景 E：硬件虽然修好了、温度降下来了，但巴氏奶超温暴露超标！Auditor 一票否决阻断放行，强制报废！
• 场景 F：网络分区或接口部分异常，系统绝不轻信片面回执，阻断并回开事件。

在这里，我们确立了一个关键设计理念：对于证据不足或商品仍存在风险的情况，系统保持停售，是设计中的正确安全结果，而不是流程失败！

07 · 原语与动作安全

ACTION TAXONOMY & GATES
⏱️ 建议用时: 30 秒
🎯 核心抓手：动作三级分类与四道闸门禁，严禁 Agent 越权处置资金 底线：绝不把物理撤销当代码回滚

在物理世界，必须遵循严格的动作分类分级：

• 可逆数字动作（如停售）：秒级下发，失败可自动重试；
• 跨系统物理动作（如派工换件）：产生真实劳务支出，通过取消改派与工单对账实施对冲补偿；
• 不可逆破坏动作（如整批报废）：必须经过移动端 HITL 人工刚性审批，严禁 Agent 越权擅自动用客户资金与资产！

所有动作必须依次穿透四道闸门：角色权限、Policy 门禁、幂等 Token 与只增审计。

涵盖多Agent必要性、大模型边界、网络异常容灾、300店真实性、商业ROI

内部防守秘籍
Q1：为什么非要用多 Agent？用一个强大的单 Agent（如 GPT-4 / Qwen-Max）配几个工具和状态机不行吗？
💡 答辩金句：“单 Agent 的硬伤不是推理能力不够，而是‘自我验证的幻觉’在物理世界具有不可承受的灾难性代价。”
  • 根因分析：大模型存在不可避免的倾向自洽偏差。若让 Executor 既派单又验收，它极易把“技工说修好了”顺理成章地推论为“柜内商品没问题”。
  • 消融实验铁证：我们在 161 项门禁测试中专门做了消融实验。移除独立 Auditor 后，面对“硬件修好但商品变质”（场景 E），单 Agent 发生了 100% 的重大食品安全事故漏检！只有引入上下文强物理隔离、只查外部传感器真值的 Auditor，才能守住安全底线。
Q2：这套系统里，大模型的作用究竟是什么？哪些是大模型做的，哪些是规则/算法做的？
💡 答辩金句：“大模型负责认知归因与非确定性决策，确定性状态机与规则算法负责刚性守门，两者的结合才是 Industrial Agent 的正确范式。”
  • 大模型负责：Diagnoser 从设备异响描述、环境温湿度历史、维修文本等多模态异构信息中推断 Top-K 假设；向店长生成自然语言案情汇报与复盘报告；
  • 确定性算法负责：500ms 毫秒级 POS 熔断、Westgard 走廊、Arrhenius 微分定损积分、Policy 权限门禁。
  • 总结：涉及资金安全和公共卫生的红线，绝对不能依靠大模型的概率掷骰子，必须由确定性门禁做绝对防御！
Q3：如果外部传感器故障、数据被破坏或者断网，Auditor 怎么防范？
💡 答辩金句：“在店巡的设计哲学里，‘证据不全’直接等价于‘绝对不安全’；保持停售是设计的正确结果，系统绝不盲目绿线通关！”
  • 容灾机制：对应不变式场景 F。当数据断流或返回 Partial 时，Auditor 判定为 BLOCKED 并触发 Reopen，系统坚决保持销售熔断锁，并升级移动端人工介入。在实体世界，“宁可错停等待人工，绝不错放危害公共安全”。
Q4：300 家门店大盘听起来很壮观，这是真实数据还是模拟？如何接入真实系统？
💡 答辩金句：“我们基于真实连锁拓扑与热力学方程建立了高保真数智孪生；真正接入真实企业，业务核心代码一行不改，只需替换两组适配器。”
  • 数据真实性：43.2 万条时序数据已在 ModelScope 开源，符合牛顿冷却定律与真实客流开门热负荷分布；
  • 接入成本极低：由于架构采用三层解耦，落地时只需接入 MQTT/HTTP 物联网网关适配器，以及连锁 ERP 停售接口，具备向万店连锁平滑灰度推广的能力。
Q5：如何量化商业价值与 ROI？
💡 答辩金句：“一降、一升、一保——降货损、升流转、保品牌生命线。”
  • 降货损：传统失温往往“一刀切”全部扔掉；通过 Arrhenius 精准时序积分，区分边缘超温与核心受损，平均挽回 30%~40% 的非必要报损；
  • 升流转：500ms 毫秒感知 + 自动调度技工，将传统平均 45 分钟的“发现-上报-派单”人工耗时压缩至秒级；
  • 保生命线：杜绝因“设备修好就放行”导致的变质食品误售事件，保护企业数十亿级的品牌声誉免受公关危机与食安重罚。
