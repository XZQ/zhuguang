# 逐光|消融对照:多 Agent 安全层的增量价值

> 消融门禁:通过
> 口径:六场景 x 四架构变体,同一确定性虚拟时钟,不调用 LLM;
> 延迟/Token/成本差异需真实 AgentTeams 运行时,不在本报告范围。

## 变体定义

| 变体 | 移除的层 | 其余部分 |
|---|---|---|
| full(基线) | 无 | 五角色 + IncidentService 聚合门 + Policy/MCP 防线 |
| no_auditor | Auditor 独立验证与聚合门 | 角色保留,Executor 自证并自我宣告关闭 |
| single_agent | 角色身份分离 | 单一身份执行全部步骤 |
| rule_only | 证据关联诊断 | 静态先验诊断,下游遏制/审批/验证保留 |

## 结论

### 移除 Auditor 独立验证:执行者自证成功

- 观察:5/6 场景被自我宣告关闭(基线错误关闭 0 起);场景 E 在设备恢复但商品处置未闭环时,尝试放行 2 个未闭环批次,5 次放行全部被审批层或 MCP release_guard(verifier 必须是 Auditor)拦截,不安全批次实际放行 0 起;场景 B 出现 2 起放行/停售状态不一致(商品已准放行但停售未解除,过度遏制)。
- 解读:独立验证是事件管理层的安全前提;没有它,关闭决定与事实脱钩。MCP 工具层的 release_guard 构成第二道防线,即使管线退化也不放行实物。

### 单一 Agent 身份:受控写在 Policy 层被拒

- 观察:6 次受控写全部被 Policy 拒绝(allowed_actors 不含 SingleAgent),0/6 场景完成遏制,事件停留在 OPEN。
- 解读:角色身份是写入路径的硬前提;单一身份的 Agent 连停售遏制都无法执行,系统以拒动方式降级保安全(fail-safe by refusal)。

### 静态先验替代证据关联诊断

- 观察:Top-1 命中 4/6(基线 6/6),错派工单 2 张(B 把传感器故障误判为压缩机故障、C 把门未关误判为压缩机故障);安全违规 0 起。
- 解读:诊断质量决定维修正确性与成本;误判时下游遏制/审批/验证层仍保证最终安全,但错误工单在真实门店意味着误修、浪费与故障未除。

## 边界

- 消融结果来自有状态 Mock 与固定 seed,证明架构各层的相对贡献,
  不代表真实门店收益;LLM 延迟/Token/成本对照需真实 AgentTeams 运行时。
- `no_auditor` 的自我宣告关闭是对单体式架构的建模:真实单 Agent 系统没有
  IncidentService 聚合门,关闭决定同样由执行者自己作出。
